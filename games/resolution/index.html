what this is, and what it assumes about hanb

Every board is 61 hexagonal cells. A cell holds a region one order of magnitude smaller than the board that contains it, so resolving a cell reveals a whole new board — the recursion that makes hanb work. You spend bits to resolve objects into cells; resolved objects produce more bits; fill all 61 and you may descend into any one of them.

Scale characters follow the published anchors. Reading the 64-character alphabet a–z A–Z 0–9 - . as indices 0–63, the exponent of a character's scale in metres is index − 36. That reproduces all three anchors in the README exactly: A = 10⁻¹⁰ m, K = 10⁰ m, . = 10²⁷ m. The address string appends the index character of each cell you descend into, so it lengthens as the object gets smaller.

Two things here are guesses rather than readings, and are easy to change. Boards alternate between flat-top and pointy-top orientation with depth, which is how I read "the rotations differ between levels". And cells fill outward in a spiral from the centre, which the notation does not specify.

The economics are the ones worked out on the plates: prices within a kind rise by 1.15 each time, each additional cell on a board costs 6% more than the last, upgrades multiply rather than add, and every scale is arithmetically identical to every other — so a board always takes about the same time to fill, however large the numbers on it have become. That last property is the whole point.
